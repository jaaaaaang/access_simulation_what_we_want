# RF-SIM 비즈니스 로직 개발 문서

> **대상**: TDE 개발팀 / 기획팀  
> **버전**: RF-SIM v1.0.4  
> **최종 업데이트**: 2026-06-17

---

## 1. 목적

RF-SIM은 통신 장비(안테나)의 **RF 커버리지를 시뮬레이션하고 최적 기지국 배치를 자동으로 계산**하는 네트워크 최적화 도구입니다.

주요 목적은 아래 세 가지입니다.

- 아파트 단지 등 건물군에 대한 **베란다(유리창) 전파 수신률** 사전 예측
- **최소한의 기지국 폴대(Pole) 수**로 목표 커버리지(%)를 달성하는 최적 배치 계산
- 시뮬레이션 결과를 GeoJSON·보고서 형태로 **타사 GIS 도구 연동** 가능하도록 제공

---

## 2. 시뮬레이션 로직

### 2-1. 타겟 등급 분류

건물 외벽을 전파 수신 가능성에 따라 3개 등급으로 자동 분류합니다.

| 등급 | 명칭 | 판정 기준 | 점수 가중치 | 비고 |
|------|------|-----------|-------------|------|
| 1등급 | Primary 베란다 | 사용자가 직접 캔버스에 그린 선분 | **100% (1.0)** | 유리창 구조 — 전파 인입 최우선 대상 |
| 2등급 | Second 베란다 (긴 벽면) | 건물 Polygon 각 모서리 길이 중 **평균 이상인 벽체**를 자동 추출 | **70% (0.7)** | 콘크리트 혼합 벽체 — 차순위 대상 |
| 3등급 | 짧은 측면 벽 | 건물 평균 모서리 길이 미만인 벽체 | **0% (노카운트)** | 고밀도 콘크리트 옹벽 — 분석 제외 |

> Second 베란다는 건물 Polygon에서 `getSecondVerandas()` 함수가 자동 추출합니다. 사용자가 별도로 그릴 필요 없이 건물만 그리면 자동 적용됩니다.

---

### 2-2. 샘플링 — 타겟 좌표 생성

베란다 선분을 **1m 간격**으로 이산 샘플 좌표로 변환합니다.

- 샘플 간격: `1m = pixelsPerMeter px` (기본값 `pixelsPerMeter = 2`, 즉 2px = 1m)
- 1개 샘플 포인트 = 1m의 물리적 베란다 거리
- 최대 샘플 수 제한 없음 (실제 물리 공간 기반 개방형 산출)
- Primary 베란다와 Second 베란다는 별도 배열로 관리됨

---

### 2-3. 전파 평가 엔진 (`evaluateRay`)

각 안테나 장비와 샘플 포인트 사이의 전파 수신 가능 여부를 다음 4단계로 계산합니다.

#### ① 거리 감쇄 (f_d)

| 거리 범위 | 신호 강도 |
|-----------|-----------|
| d ≤ 70m | 100% (f_d = 1.0) |
| 70m < d ≤ 100m | 90% (f_d = 0.9) |
| 100m < d ≤ 150m | 85% (f_d = 0.85) |
| d > maxRange (기본 150m) | 0% — 신호 두절 |

#### ② 빔폭 각도 손실 (Angular Loss)

- **메인 로브** (`diff ≤ beamWidth / 2`): Cosine² 기반 공간 감쇄 적용
- **회절/엣지 누설 구간** (`beamWidth/2` ~ `beamWidth/2 + 15°`): 0.5에서 0까지 선형 감쇄
- **빔 범위 외** (`diff > beamWidth/2 + 15°`): 신호 = 0

#### ③ LOS(Line of Sight) 차단 판정

안테나에서 샘플 포인트까지 3px 간격으로 레이캐스트를 수행합니다. 중간 경로에 **다른 건물 Polygon 내부**가 검출되면 `score = 0` 처리합니다. 자신이 위치한 건물은 차단 체크에서 제외됩니다.

#### ④ 수신각 법선 벡터 판정 (Normal Cosine Rule)

벽면 외향 법선 벡터와 전파 도달 벡터의 내적(`cos_phi`)이 0 이하이면 수신 불가 처리합니다. 벽 반대쪽에서 건물을 관통하는 비현실적인 경로를 차단합니다.

**최종 Score 산식:**

```
score = cos_phi × f_d × angular_loss
(Second 베란다의 경우: score × 0.7)
```

반환값이 `> 0.05`인 경우만 유효 수신으로 인정합니다.

---

### 2-4. 시뮬레이션 실행 흐름

시뮬레이션은 3개 Phase로 순차 실행됩니다.

```
[Phase 1] 수동 장비 평가
     ↓ 커버리지 미달 시
[Phase 2] 3분기 자동 최적화 루프 (Greedy)
     ↓ 완료 후
[Phase 3] Second 베란다 보너스 집계
```

#### Phase 1 — 수동 장비 우선 평가

사용자가 캔버스에 직접 배치한 기지국 국소(Manual Site)를 먼저 처리합니다.

- 각 Manual 장비에 대해 전체 Primary 샘플에 `evaluateRay` 수행
- `score > 0.05`인 샘플은 `covered = true`로 마킹하고 가중치 점수 누적
- 자신이 위치한 건물(`bIdx`)의 베란다는 자가 수신 방지 규칙으로 제외

#### Phase 2 — 3분기 자동 최적화 루프 (Greedy Multi-Sector Placement)

목표 커버리지에 도달할 때까지 반복 수행합니다.

**3분기 고정 배치 원칙**

- 1개 국소(Pole)에는 반드시 **3개 안테나 섹터(A, B, C)가 동시 배치**
- 각 섹터 간 각도 이격: **최소 80도 이상** (간섭 방지)
- 자동 배치 시 각도 조합: 0°~350°를 10° 단위로 순회하며 최적 3방향 조합 탐색

**최적화 루프 절차**

1. 모든 건물 경계면의 후보 위치(`candidatePoints`) 생성 (10px 간격)
2. 각 후보 위치에서 36 방향 × 전체 미수신 샘플의 레이 스코어 행렬 사전 계산
3. 3개 섹터 조합(A·B·C) 중 `joint coverage score`가 최대인 조합 선정
4. **Strict CoLocation** 활성화 시: 기존 확립된 폴 위치와 동일한 후보에 **×1.30 가산 배수** 적용 → 폴 수 최소화 유도
5. 최적 위치에 3개 안테나 동시 배치, 커버리지 갱신
6. 목표 달성 또는 최대 40회 반복 소진 시 종료

#### Phase 3 — Second 베란다 보너스 집계

자동/수동 장비 배치가 완료된 후, Second 베란다(건물 긴 벽면) 샘플들에 대해 전파 도달 여부를 평가합니다. Primary 커버리지 모수에는 포함되지 않고 **보너스 미터(+Xm)** 로 별도 표시됩니다.

---

## 3. 결과 Output

### 3-1. 커버리지 달성률

```
최종 커버리지 (%) = (수신 완료 샘플의 가중치 점수합 / 전체 샘플 가중치 점수합) × 100
```

- Primary 베란다만 모수(분모)에 포함
- Second 베란다 수신 결과는 `+Xm 보너스`로 별도 표시

### 3-2. 건물별 커버리지

시뮬레이션 완료 후 캔버스 각 건물 중앙에 아래 정보가 오버레이됩니다.

| 항목 | 내용 |
|------|------|
| 달성률 (%) | 해당 건물 Primary 베란다 커버리지 비율 |
| 색상 코드 | 녹색 ≥ 90% / 주황 ≥ 50% / 빨강 < 50% |
| +Xm 보너스 | Second 베란다 수신 미터 수 (해당 시 표시) |

### 3-3. 장비 배치 정보 (Equipments)

| 필드 | 설명 |
|------|------|
| `id` | 예: `AUTO-1-A`, `AUTO-1-B`, `AUTO-1-C` (자동), `M-1-A` (수동) |
| `x`, `y` | 캔버스 픽셀 좌표 |
| `angle` | 안테나 지향각 (도, 0° = 북쪽/위) |
| `bIdx` | 설치된 건물 인덱스 (0-based) |
| `coveredPoints` | 해당 섹터가 담당하는 수신 완료 샘플 좌표 배열 |

### 3-4. 시뮬레이션 로그

각 국소 배치 시 아래 내용이 로그로 기록됩니다.

- 배치 유형 (MANUAL / AUTO-SITE)
- 위치 좌표 및 건물 번호 (Building #N)
- 지향각 3방향
- 확보된 커버리지 미터 수

### 3-5. 파일 다운로드

| 파일 | 내용 |
|------|------|
| `rf_simulation_results.zip` | PNG 스크린샷 + 텍스트 리포트 (설정값 + 로그 + AI 분석) |
| `rf_topology_project.json` | 작업 상태 저장 파일 (건물·베란다·수동 장비·배경이미지 포함) |
| `rf_topology_geojson.json` | 건물 Polygon + 베란다 좌표를 GeoJSON 형식으로 내보내기 (QGIS 등 연동) |

### 3-6. AI Insights

시뮬레이션 완료 후 `AI Insights` 버튼 클릭 시 Gemini 모델이 결과를 분석하여 아래 내용을 한국어 마크다운으로 출력합니다.

- 전체 커버리지 효율 평가
- 개별 장비 효율 지표 (Score ÷ Meters × 100) 기반 과잉/불량 장비 식별
- 장비 통합·제거 권고
- 네트워크 ROI 개선 방안 제안

## 1-1. VWorld 아파트 검색 (GIS 연동)

VWorld Open API를 통해 실제 아파트 단지의 건물 Polygon을 자동으로 가져오는 기능입니다.

| 파라미터 | 입력 형식 | 역할 설명 |
|----------|-----------|-----------|
| **VWorld 인증키** | 문자열 (password 마스킹) | VWorld 오픈플랫폼에서 발급받은 API 인증키를 입력합니다. 입력값은 브라우저 localStorage에 저장되어 재사용됩니다. |
| **VWorld 등록 도메인** | 도메인 URL | 인증키 발급 시 등록한 도메인과 일치해야 합니다. 기본값은 현재 접속 도메인(`window.location.origin`)으로 자동 설정됩니다. |
| **API 호출 방식** | 직접 호출 / 서버 프록시 | **직접 호출(JSONP)**: 브라우저에서 직접 VWorld API를 호출합니다. 서버 IP 차단(WAF)을 우회할 수 있어 권장 방식입니다. **서버 프록시**: `/api/vworld-proxy`를 경유하여 호출합니다. 서버 IP가 VWorld에서 차단될 경우 오류가 발생할 수 있습니다. |
| **조회 레이어** | `LT_C_SPBD` / `LT_C_BLDINFO` | **도로명건물(SPBD)**: 도로명주소 기준 건물 Polygon. **건축물정보(BLD)**: 건축물 대장 기반 상세 정보. 대부분의 경우 SPBD 권장. |
| **단지명 동 필터링** | 체크박스 | 활성화 시 검색어 첫 단어를 건물명(`buld_nm`) 필터로 추가 적용합니다. 동일 영역의 다른 단지 건물이 섞이는 것을 방지합니다. |
| **아파트 단지명** | 텍스트 (예: 은마아파트) | 검색어를 입력하고 검색 버튼 또는 Enter를 누르면 VWorld Search API 2.0으로 후보 위치를 조회합니다. 결과 선택 시 해당 영역의 건물 Polygon을 자동으로 캔버스에 로드합니다. |

## 2. Draw Areas 섹션

캔버스에 건물·베란다·장비를 직접 그리는 도구 모음입니다.

| 도구 | 조작 방법 | 역할 설명 |
|------|-----------|-----------|
| **Building** | 좌클릭으로 꼭짓점 추가 → 우클릭으로 Polygon 완성 | 건물 외곽선(Polygon)을 그립니다. 전파 차단 장애물로 작동하며, Second 베란다(긴 벽면)가 자동 추출됩니다. 꼭짓점이 3개 미만이면 우클릭 시 취소됩니다. |
| **1st 베란다** | 시작점 클릭 → 끝점 클릭 | 유리창 구조의 Primary 베란다 선분을 그립니다. **점수 가중치 100%** — 시뮬레이션 핵심 커버리지 대상입니다. 캔버스에서 황색(#ffb300) 실선으로 표시됩니다. |
| **2nd 베란다** | 시작점 클릭 → 끝점 클릭 | 콘크리트 혼합 벽체를 수동으로 지정합니다. **점수 가중치 70%** — 보조 커버리지 대상입니다. 캔버스에서 하늘색(#29b6f6) 점선으로 표시됩니다. |
| **Eraser** | 대상 클릭 | 클릭 위치의 요소를 제거합니다. Z-index 우선순위: ① 수동 장비(반경 10px) → ② 베란다(선분 10px 이내) → ③ 건물(Point-in-Polygon). 건물 삭제 시 해당 건물에 연결된 수동 장비도 함께 제거됩니다. |
| **Place Site** | 클릭 | 클릭 위치에 3분기 국소(Tri-Sector Site)를 배치합니다. 건물 내부 클릭 시 가장 가까운 건물 모서리로 자동 스냅됩니다. 배치 즉시 섹터 A(0°) / B(120°) / C(240°) 3개 안테나가 동시 생성됩니다. |
| **Clear All** | 버튼 클릭 | 캔버스의 모든 요소(건물·베란다·수동 장비·시뮬레이션 결과)를 초기화합니다. |

## 3. Parameters 섹션

시뮬레이션 물리 파라미터를 설정합니다.

| 파라미터 | 기본값 | 단위 | 역할 설명 |
|----------|--------|------|-----------|
| **Pixels per Meter (Scale)** | 2 | px/m | 캔버스 픽셀과 실제 물리 거리(미터)의 변환 비율입니다. `pixelsPerMeter = 2`이면 2px = 1m. 이 값을 기준으로 샘플 간격·거리 감쇄·최대 범위가 모두 계산됩니다. 지도 스케일에 맞게 조정이 필요합니다. |
| **Target Coverage (%)** | 65 | % | 자동 최적화 루프가 달성을 목표로 하는 Primary 베란다 커버리지 비율입니다. 이 값에 도달하면 자동 배치가 중단됩니다. `Evaluate Setup Only` 실행 시에는 무시됩니다. |
| **Beam Width (°)** | 60 | 도(°) | 안테나 주빔의 반전력빔폭(HPBW)입니다. 이 각도 범위 내에서는 Cosine² 기반 감쇄가 적용되고, ±15° 추가 범위까지 엣지 누설이 허용됩니다. 값이 클수록 넓은 방향을 커버하지만 단위 방향 이득이 낮아집니다. |
| **Max Range (m)** | 150 | m | 안테나 신호가 도달 가능한 최대 물리 거리입니다. 이 거리를 초과한 샘플은 점수 0으로 처리됩니다. 캔버스에서 빔 반경 시각화는 `maxRange × pixelsPerMeter × 0.4` 크기로 표시됩니다. |
| **Strict 1 Pole / Building** (CoLocation) | ON | 체크박스 | 활성화 시 동일 건물에 이미 폴이 설치된 경우 다른 위치에 추가 폴 설치를 차단합니다. 자동 최적화 시 기존 폴 위치 재사용에 **×1.30 가산 배수**를 적용하여 전체 폴 수를 글로벌 최소화합니다. 네트워크 구축 비용 절감 목적입니다. |

## 4. Manual Nodes 섹션

수동으로 배치한 국소(Site) 안테나를 관리합니다.

| 항목 | 역할 설명 |
|------|-----------|
| **장비 ID** (예: M-1-A) | `M-{국소번호}-{섹터}` 형식. 국소 번호는 배치 순서대로 자동 부여됩니다. |
| **Angle 슬라이더** (0°~359°) | 해당 안테나의 지향각을 조정합니다. 동일 위치의 다른 섹터와 각도 차이가 **80도 미만**이 되면 변경이 차단되고 경고가 표시됩니다. |
| **Remove 버튼** | 해당 국소의 **3개 섹터 전체**를 동시에 삭제합니다. 단일 섹터만 삭제하는 것은 불가합니다. |

## 5. 실행 버튼

| 버튼 | 활성화 조건 | 역할 설명 |
|------|-------------|-----------|
| **Evaluate Setup Only** | 건물 ≥ 1개 + 수동 장비 ≥ 1개 | `targetCoverage = 0`으로 설정하여 자동 배치 없이 수동 배치 장비의 커버리지만 계산합니다. 수동 배치 성능을 검증할 때 사용합니다. |
| **Auto Populate & Optimize** | 건물 ≥ 1개 + 베란다 ≥ 1개 | 수동 장비를 먼저 평가한 후, 목표 커버리지 미달 시 자동 3분기 최적화 루프를 실행합니다. |
