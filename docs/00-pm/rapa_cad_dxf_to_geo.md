## 2. 어떤 변환을 했나 (파이프라인 상세)

```
DWG ──(ODA File Converter)──▶ ASCII DXF
DXF ──▶ ① 파싱 ──▶ ② 평탄화 ──▶ ③ 시트 탐지 ──▶ ④ footprint 추출
     ──▶ ⑤ 주기 매핑 ──▶ ⑥ 지오레퍼런싱 ──▶ ⑦ m-RAPA JSON + QA
```

**① DXF 스트리밍 파싱** — (code, value) 페어 스트림으로 ENTITIES+BLOCKS 파싱. 858개 블록, 폴리라인 VERTEX 그룹핑, 블록 기준점 수집. ezdxf 없는 폐쇄망에서도 동작하는 순수 파이썬.

**② INSERT 재귀 평탄화** — 중첩 블록 삽입(위치·축척·회전)을 절대좌표로 전개 → 31만 개 엔티티. 층수 텍스트("23F(22U)")·건물 선형·심볼은 대부분 블록 내부에 있어 이 단계가 필수.

**③ 옥외배치도 시트 탐지** — 한 모델공간에 표지/범례/설치예시도/옥외배치도/지하·지상 평면도/계통도가 나란히 배치됨. 도곽 하단 ATTRIB 타이틀("이동통신 구내중계설비 옥외배치도")의 x좌표 + 시트 간격으로 대상 영역을 자동 산출. *(주의: 우측 하단의 작은 보조 타이틀을 잡으면 영역이 밀림 — 정식 도곽 ATTRIB 우선 규칙으로 해결)*

**④ 건물 footprint 추출** — 핵심 난점: 건물이 닫힌 폴리곤이 아니라 세대 평면 블록 조합(선분 수천 개)으로 그려져 있고, 전체 선형을 채우면 지하주차장·조경 선으로 전 동이 한 덩어리로 붙음. 해법:
1. 지번 라벨을 가장 많이 포함한 블록 = 지적도 블록으로 자동 식별·제외
2. 후보 블록별로 단독 래스터화(50mm/px) → 팽창 → 연결요소 → **"동 라벨과 1:1 매칭되는 컴포넌트 수"로 스코어링** → 건축 원도 블록(이 도면에선 'AA') 자동 선택
3. 동별 컴포넌트: 구멍 채움 → 팽창 역보정(침식) → 외곽 컨투어 → Douglas-Peucker 단순화 → mm 폴리곤

**⑤ 주기 매핑** — 동 라벨(3자리 숫자 텍스트)로 동 번호 부여, "nF(mU)" 패턴 텍스트를 폴리곤 포함/최근접으로 배정해 `floors_above = max(nF)`, 파란 원(color 5)=관로동·빨간 원(color 1/240)=옥상형을 심볼 블록 유래 여부로 필터링(범례·설치예시도 인셋 제외) 후 동별 배정.

**⑥ 지오레퍼런싱 (정밀)** — 단일 지오코딩 앵커 대신:
1. 도면 지적도에서 주변 필지 지번 라벨 249개 추출 → 8방위 섹터별 대표 8개 선정
2. 각 지번("대구 동구 신암동 226-17" 등) 지오코딩 → **GCP 8점**
3. Helmert(similarity) 최소자승 적합. 자유 적합 결과 축척 0.99837e-3(실축 mm 검증)·회전 39.86° → 축척 1e-3 고정 재적합
4. **독립 교차검증**: 도면 방위표('방위' 블록) 화살표 방향에서 계산한 회전각 39.52° vs GCP 적합 39.86° (차이 0.34°)
5. 잔차 **RMS 4.0m / 최대 6.4m** (지오코딩된 필지 중심 vs 도면 라벨 위치 차이 수준)

**⑦ 출력** — m-RAPA 샘플 스키마 준수 + 확장 필드(`is_duct_building`, `rooftop_repeater_count`, `floor_marks`, `footprint_area_m2`, `georeference` 메타). height는 도면에 없어 층수×2.9m 추정치로 명시.

## 3. 소스 파일별 비교 (DWG vs DXF vs 캡처 이미지)

| 구분 | DWG (원본) | **DXF (ASCII) — 권장** | 캡처 이미지 |
|---|---|---|---|
| 파싱 가능성 | 독점 바이너리. 순수 파이썬 불가, libredwg는 신버전 호환 불완전 | 텍스트 포맷, 어느 환경에서나 파싱 가능 | Vision 모델/CV로만 해석 |
| 필요 전처리 | — (원본) | ODA File Converter 변환 1회 (무료, CLI 배치화 가능, 로컬 처리라 도면 유출 없음) | 없음 |
| 좌표 정밀도 | (변환 후 DXF와 동일) | **실축 mm 좌표** — 축척이 데이터로 확정, 폴리곤 오차 ≈ 래스터 해상도 5cm | 픽셀 해상도 의존. 1920px 캡처에 200m 단지면 1px≈10cm이지만 앨리어싱·선 두께로 실효 30cm~1m |
| 텍스트(층수/동/지번) | 〃 | **문자열 그대로 추출, 오류율 0** — 층수·지번 GCP의 원천 | OCR 필요. 작은 "23F(22U)"·지번 라벨은 오인식 잦음, 지번 GCP 사실상 불가 |
| 레이어/블록 의미 | 〃 | 레이어명(RAPA_*)·심볼 블록명·색상 코드로 **관로동/옥상형을 결정적으로 분류** | 색상 픽셀 기반 추정만 가능. 범례 vs 실배치 구분이 취약 |
| 방위/축척 | 〃 | 방위표 블록에서 회전각 계산, 축척은 좌표 자체 | 북쪽 화살표를 vision으로 판독(±수°), 축척바 판독 필요 |
| 지오레퍼런싱 | 〃 | 지번 GCP 다점 적합 → **RMS ~4m** | 앵커 수동 지정 또는 지도 매칭 필요 → 수십 m급 |
| 이번 케이스 결과 | 변환 경유 | **10/10동, 층수·분류 전 항목 정합, RMS 4.0m, 20초** | (미수행 — 예상: 폴리곤은 근사 추출 가능하나 층수 텍스트·지번 GCP 손실로 품질 크게 저하) |

**결론**: 파이프라인 표준 입력은 **DXF**로 고정하고, DWG는 ODA 변환을 전처리 단계로 자동화. 캡처 이미지는 도면 파일이 정말 없을 때의 최후 폴백으로만 사용 (폴리곤 형상은 얻어도 층수·정밀 좌표는 반자동 보정 필요).

## 4. 모듈화/패키징 방안

### 구조 (첨부 `rapa_dxf_extract.zip`, 검증 완료)
```
rapa_dxf_extract/
  dxf_io.py        # AC1003+ ASCII DXF 스트리밍 파서 (ezdxf 불필요)
  flatten.py       # INSERT 재귀 전개 (ARC 폴리라인 근사 포함)
  siteplan.py      # 옥외배치도 시트 영역 자동 탐지
  annotations.py   # 동 라벨 / nF(mU) 층수 / 파란·빨간 심볼 (범례·예시 제외)
  footprints.py    # 지적블록 자동 제외 + 소스블록 스코어링 + 래스터 footprint
  georef.py        # 지번 GCP 후보 선정, Helmert 적합, 방위표 검증
  output.py        # m-RAPA JSON + Leaflet QA HTML
  pipeline.py      # run() 엔드투엔드
  cli.py           # python -m rapa_dxf_extract.cli
```

### 시뮬레이터 통합 (rf-los-simulator)
```python
# buildingSource 분기: DB 폴리곤 부재 시
if complex_polygon_missing(rapa_key):
    from rapa_dxf_extract import run
    result = run(dxf_path, rapa_key=rapa_key,
                 geocoder=kakao_geocoder,   # 사내 지오코딩 어댑터 주입
                 addr_prefix=admin_addr)     # "대구 동구 신암동"
    save_to_db(result)   # buildingSource="dxf_extraction(...)"
```
- **지오코더는 주입식 인터페이스** — Kakao/Naver/VWorld 등 사내 가용 API를 어댑터로 연결 (Google Places보다 국내 지번 정확도 유리). 폐쇄망이면 `gcp_file`로 사전 지오코딩 결과 공급, 미제공 시 로컬 mm 좌표로라도 산출
- CISS에 단지 폴리곤이 뒤늦게 생기면 그 폴리곤 대응점으로 Helmert 재적합만 다시 수행 (`georef.fit_helmert`) → 잔차 사실상 0으로 수렴
- DWG 접수 시: ODA File Converter CLI를 워커 앞단에 배치 (`ODAFileConverter in out ACAD12 DXF 0 1`)

### 권장 아키텍처: **하이브리드 (결정론 코드 우선 + LLM 폴백)**
```
도면 접수 → [A] rapa_dxf_extract 실행 (20초, 토큰 0)
              ├─ 성공 + 검증 통과 → JSON 저장
              └─ 실패/저신뢰 (라벨매칭<70%, 동 수 불일치, GCP<3점 등)
                    → [B] LLM 에이전트 폴백 (코드실행 도구 + 본 패키지를 스킬로 제공)
                    → [C] 이미지 입력이면 vision 추출 (근사 폴리곤 + 사람 검수 플래그)
```
자동 검증 게이트(코드에 내장된 신호): 시트 탐지 성공, footprint-라벨 매칭율, 동 수, RAPA_TABL 링 면적 대비 오차, GCP RMS, 방위표-GCP 회전각 차. 이 게이트 덕에 대부분 도면은 토큰 소모 없이 처리되고, LLM은 변형 도면에만 투입됩니다.

## 6. 한계와 다음 단계

1. **일반화 검증 필요** — 현재 자동화 로직(도곽 ATTRIB, RAPA_* 레이어, 심볼 블록명, 동 라벨 3자리 규칙)은 RAPA 표준 도면 규약 기반. 타 설계사 도면 5–10건으로 회귀 테스트 세트 구축을 권장 (검증 게이트가 실패를 스스로 신고하도록 설계되어 있음)
2. **height 추정치** — 층수×2.9m. CISS/건축물대장 연계 시 실측치로 교체
3. **관로동 0건 케이스** — 이 도면은 파란 심볼이 범례에만 존재. 파란 점이 실제 배치된 도면 1건으로 양성 케이스 검증 필요
4. **지오레퍼런싱 상한** — 지번 지오코딩 품질에 종속(RMS ~4m). CISS 단지 폴리곤 제공 시 재적합으로 <1m 가능
5. DXF 버전 — 파서는 AC1003(R12급) ASCII 기준. ODA 변환 프로파일을 "ASCII DXF R12"로 고정하면 전 도면 호환
