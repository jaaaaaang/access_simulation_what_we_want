## 1. Save Topology vs DB 저장 (역할 구분)

| | **Save Topology** (기존, 유지) | **DB 저장** (신규) |
|---|---|---|
| 목적 | 현재 작업 세션 **export** | 원본 **마스터 데이터 교정** |
| 대상 | 건물 + 베란다 + 장비 + 캔버스 상태 | 건물 폴리곤 (지오메트리)만 |
| 좌표계 | 캔버스 px | 위경도 (lon/lat) |
| 출력 | `rf_topology_project.json` 브라우저 다운로드 | `public/temps/<rapaKey>.json` 덮어쓰기 |
| 재사용 | Load Topology로 직접 불러와야 함 | 같은 RAPA Key를 **다시 선택하면 자동 반영**, LOS 배치도 같은 파일을 읽음 |

## 2. DB 저장 동작

### 2.1 사용 흐름
1. 상단바에서 RAPA Key 선택 → 단지/건물 폴리곤 로드
2. **지우개**로 중첩·불량 폴리곤 삭제 (필요 시 건물 그리기로 재작성)
3. 좌측 `1. Base Map or GIS` 패널 → **`DB 저장 (원본 반영)`** 클릭
4. 확인 대화상자에 유지/수정/추가/삭제 동수가 표시됨 → 확인 시 저장

### 2.2 건물 매칭 규칙 (`mergeEditedBuildings`)
배열 인덱스에 의존하지 않는다 — 지우개로 중간 건물이 삭제되면 인덱스가 밀리기 때문.

| 판정 | 조건 | 처리 |
|---|---|---|
| **유지 (kept)** | 정점 수 동일 + 모든 정점 0.5px 이내 | 원본 위경도를 **그대로 보존** (왕복 오차 0) |
| **수정 (edited)** | 중심점이 임계거리(캔버스 단변의 5%) 이내인 미매칭 원본과 짝지음 | 폴리곤만 교체, 층수·건물코드 등 메타데이터 보존 |
| **추가 (added)** | 짝지을 원본 없음 | 신규 레코드 (`ciss_bld_cd`/층수 = null) |
| **삭제 (removed)** | 화면에서 짝지을 대상이 사라진 원본 | 저장 대상에서 제외 |

출력 순서는 원본 순서를 유지하고 신규 건물만 뒤에 덧붙여 파일 diff를 최소화한다.
동일 좌표 중복 건물(중첩 버그의 전형)도 1:1로 소진 매칭되어, 둘 중 하나만 지우면 정확히 하나만 삭제된다.

### 2.3 안전장치
- **최초 1회 자동 백업**: `public/temps/_backup/<rapaKey>.json` (재저장 시 덮어쓰지 않아 최초 원본이 계속 보존됨)
- **원본으로 복원** 버튼: 백업본으로 되돌림 (복원 후 대상을 다시 선택해야 화면 반영)
- **경로 탈출 차단**: rapaKey는 `^[A-Za-z0-9._-]+$`만 허용, `..` 금지, 경로 재확인
- 전체 건물이 삭제된 상태로는 저장 불가
- 변경분이 0이면 저장하지 않고 알림만 표시
- `_edit` 메타 기록: `firstEditedAt`, `editedAt`, `source`, `buildingCount`

### 2.4 API
| 메서드 | 경로 | 설명 |
|---|---|---|
| POST | `/api/moira-polygon/save` | `{rapaKey, data}` → temps JSON 덮어쓰기 (+최초 백업) |
| POST | `/api/moira-polygon/restore` | 백업본으로 복원 (백업 없으면 404) |
| GET | `/api/temps/list?q=` | rapaKey 부분 일치 목록 (단지명/건물수/교정여부) |

> 서버 경유 파일 쓰기이므로 **`npm run dev`(tsx server.ts)로 실행 중이어야** 동작한다.
> `npm start`(vite 단독)에서는 저장 API가 없어 실패 알림이 뜬다.

## 3. RAPA Key 부분검색

- 상단바 RAPA Key 드롭다운 **왼쪽**에 검색 입력창 추가
- 키 일부(예: `2206-3699`) 또는 단지명으로 매칭, 상위 30건
- Enter → 첫 번째 결과 즉시 조회 / Esc → 닫기 / 항목 클릭 → 기존 `handleSelectRapaKey` 그대로 사용
- 각 항목에 temps 캐시 배지 표시: `캐시 N동` (원본) / `교정됨 N동` (DB 저장 이력 있음)
- 드롭다운은 `.shell-topbar-row`의 `overflow-y:hidden`에 잘리므로 **body 포털 + fixed 위치**로 렌더

## 5. 참고: 중첩 폴리곤 자동 탐지 (전수 조사)

288개 단지 전수 스캔 결과 — 중첩 의심 **486쌍 / 관련 건물 829동 / 135개 단지** (전체 단지의 46.9%).
판정 기준: 두 건물의 bbox가 겹치고, 한쪽의 정점+변중점 표본 중 15% 이상이 다른 쪽 내부에 포함.
완전 포함(ratio 1.0) 사례가 다수이며, 대부분 **1층 부속동 레코드가 고층 주동과 완전히 겹치는** 패턴이다.
(예: `m-RAPA-2404-0904` b1↔b78, `m-RAPA-2210-5659` b0↔b1, `m-RAPA-2302-0515` b6↔b44)

→ 이를 앱에서 자동 하이라이트해 교정 대상을 바로 짚어주는 기능은 별도 요청 시 추가 가능.
